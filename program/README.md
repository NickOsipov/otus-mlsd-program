# OTUS. ML System Design

# Программа курса ML System Design

## О курсе

Курс посвящён проектированию систем машинного обучения. Каждое занятие соответствует одному разделу шаблона `design-doc-template.md`: студент изучает раздел, разбирает его на учебном кейсе и заполняет в собственном документе.

За курс каждый студент индивидуально проектирует одну ML-систему и получает готовый design doc, пригодный для передачи заказчику, архитектору и команде разработки.

**Формат курса:**
- 3 учебных модуля по 4 занятия - 12 занятий по теории и практике ML System Design;
- итоговый модуль: консультация, предзащита, защита, подведение итогов;
- занятия онлайн, два раза в неделю, по 90 минут;
- сквозной проект выполняется индивидуально;
- тема выбирается после первого занятия и не меняется до конца курса;
- 4 накопительных домашних задания: после занятий 4, 6, 8 и 10;
- design doc ведётся в git.

**Принцип построения программы:** одно занятие - один раздел design doc. Единственное исключение - раздел 4 «Архитектура системы»: восемь подразделов невозможно проработать за 90 минут, поэтому он разделён на два занятия (архитектура и нагрузка / эксплуатационная готовность).

# Модуль 4. Итоговый проект

**Что мы сделаем в модуле:**
- Устраним противоречия между разделами документа и допишем Overview проекта.
- Пройдём консультацию и предзащиту и получим перечень обязательных доработок.
- Защитим финальный design doc, пригодный для передачи заказчику, архитектору и команде разработки.

**Компетенции модуля:**
- готовить и защищать целостный design doc ML-системы как основу для согласования и разработки решения.

Новая теория не вводится. Студент устраняет противоречия, дописывает Overview, проходит консультацию и предзащиту, затем защищает финальный документ.

## Этапы

### 1. Организация итоговой работы

- фиксация версии и границ проекта;
- проверка полноты разделов 1-12;
- индивидуальный план доработки.

### 2. Консультация по проекту и домашним заданиям

- разбор противоречий между бизнес-целью, метриками и архитектурой;
- проверка расчётов нагрузки, стоимости и экономического эффекта;
- рекомендации к предзащите.

### 3. Предзащита

**Цель:** найти критические пробелы до финальной оценки.

Студент объясняет:
- почему выбрана эта ML-постановка и какие альтернативы отвергнуты;
- как ML-метрики связаны с бизнес-метриками;
- откуда взялись числа в расчётах нагрузки и стоимости;
- какой компонент первым ограничит масштабирование;
- как система развёртывается, мониторится, переобучается и откатывается;
- при каких результатах проект будет остановлен;
- какие ограничения первой версии приняты сознательно.

По итогам студент получает перечень обязательных доработок.

### 4. Финализация документа

1. **Раздел 0. Overview** - проблема, решение и ожидаемый результат в 3-5 предложениях.
2. Устранение замечаний предзащиты и противоречий между разделами.
3. Актуализация оглавления, форматирование и вычитка.
4. Отметки в разделе 12 о пройденном ревью.

### 5. Защита проектной работы

**Формат:** 15 минут презентация и 10 минут вопросы.

**Итоговый артефакт:** design doc ML-системы, пригодный для передачи заказчику, архитектору и команде разработки.
